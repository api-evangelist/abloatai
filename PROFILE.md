# Ablo

Coordination/collaboration infrastructure for AI agents — one API that lets agents, apps, and services claim, change, and confirm the same database rows using durable claims (leases with wait-lines) plus guarded, idempotent writes that return receipts and reject stale writes.

- **Provider:** https://www.abloatai.com
- **Documentation:** https://docs.abloatai.com
- **Base URL:** https://api.abloatai.com/api

## APIs

- **Ablo API** — REST API for multi-agent coordination over shared state: models (row CRUD), durable claims with wait-lines, credentials, branches, schema, logs, and commits. Bearer-token auth, version 0.55.0. (`https://api.abloatai.com/api`)

> Ablo exposes a REST API at https://api.abloatai.com/api (/api/v1), Bearer-token auth, v0.55.0, backed by an OpenAPI contract declared at https://docs.abloatai.com/openapi.json (rendered reference confirms it). An llms.txt is declared at https://docs.abloatai.com/llms.txt and a loadable agent skill ships at @abloatai/mcp/skill.md (plus AGENTS.md in the GitHub repo), making this strongly agent-native. Two MCP servers exist: (1) a LOCAL stdio coordination/data-plane server via npm package @abloatai/mcp (run with `npx -y @abloatai/mcp`) — NOT cataloged as MCPServer because it is local/stdio; (2) an integration-helper MCP server mounted at /api/mcp on the customer's OWN app instance (https://<your-app>/api/mcp, no auth, docs/scaffolding only) — not a provider-hosted fixed public endpoint, so not cataloged as MCPServer. No AsyncAPI/GraphQL/Postman found (a WebSocket transport exists but no AsyncAPI document). Caveat: raw openapi.json and llms.txt could not be independently fetched in-session (fetch-context restriction, not 404); recommend a manual GET to confirm live payloads. Also available: TypeScript/JS SDK @abloatai/ablo, React bindings, CLI, and webhooks.
